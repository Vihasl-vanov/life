
## Что такое Generics в Java?

**Ответ:** Generics (обобщения) позволяют создавать классы, интерфейсы и методы с параметризованными типами, что обеспечивает безопасность типов на этапе компиляции.
##  Зачем нужны Generics?

**Ответ:**
- Безопасность типов (избегание `ClassCastException`).
- Устранение необходимости приведения типов.
- Повышение читаемости кода.
##  Какие преимущества у Generics перед "сырыми" типами (raw types)?

**Ответ:**
- Контроль типов на этапе компиляции.
- Нет необходимости в ручном приведении (`(String) list.get(0)`).
- Уменьшение ошибок runtime

##  Что такое "стирание типов" (type erasure)?

**Ответ:** Это процесс, при котором компилятор заменяет Generic-типы на `Object` или их верхнюю границу (`extends`), а затем удаляет информацию о типах во время выполнения.
**Примитивы не являются объектами** → они не наследуются от `Object`, поэтому их нельзя использовать в Generics.
##  Можно ли использовать примитивы в Generics?

**Ответ:** Нет, только ссылочные типы. Для примитивов нужно использовать их wrapper-классы (`int → Integer`).
## Что такое `List<?>` (wildcard)?

**Ответ:** Это неизвестный тип, который означает "любой тип". Используется, когда точный тип не важен.
#### **Когда использовать `List<?>`?**
- Когда метод должен работать с `List` любого типа, **но не изменять его**.
- Когда нужно только **читать** данные из коллекции.

##  В чем разница между `List<Object>` и `List<?>`?
**Разница между `List<Object>` и `List<?>` заключается в том, как они используют типизацию и ограничивают операции с элементами списка.**

### **Тип элементов в списке:**

- **`List<Object>`**: Это список, который может содержать объекты типа `Object` или любого его подтипа. Однако при использовании обобщений (`generics`) это означает, что список **ожидает элементы именно типа `Object`**.
    
- **`List<?>`**: Это список неизвестного типа. Символ подстановки `?` обозначает неизвестный тип, поэтому **список может быть любого типа**, например, `List<String>`, `List<Integer>` и т.д.

### **Добавление элементов в список:**

- **`List<Object>`**: Вы **можете добавлять любые объекты** в этот список, поскольку все классы в Java являются подтипами `Object`.
    
- **`List<?>`**: **Нельзя добавлять элементы** в этот список (кроме `null`), так как компилятор не знает, какого именно типа элементы должны быть. Это сделано для обеспечения типобезопасности.
### **Использование:**

- **`List<Object>`**: Используется, когда вы точно знаете, что список должен содержать объекты типа `Object`. Однако это ограничивает возможность работать со списками других типов, например, `List<String>` не может быть присвоен переменной типа `List<Object>`.
    
- **`List<?>`**: Применяется, когда необходимо работать с **любыми типами списков**, но без добавления новых элементов. Это полезно для методов, которые читают данные из списка, но не модифицируют его.

### **Типобезопасность и совместимость:**

- **Совместимость с другими списками:**
    - `List<String>` **не является** подтипом `List<Object>`, поэтому вы **не можете** присвоить `List<String>` переменной типа `List<Object>`.
    - `List<String>` **может быть** присвоен переменной типа `List<?>`, поскольку символ подстановки приемлет любой тип списка.

```java
List<String> stringList = new ArrayList<>();
List<Object> objectList = new ArrayList<>();
List<?> wildcardList = new ArrayList<>();

objectList = stringList; // Ошибка компиляции: несовместимые типы

wildcardList = stringList; // Правильно: List<String> можно присвоить List<?>

```

### **Итог:**

- **`List<Object>`**: Предназначен для списков, содержащих объекты типа `Object`. Позволяет добавлять элементы, но не совместим со списками других типов без приведения.
    
- **`List<?>`**: Обобщенный тип списка неизвестного типа. **Не позволяет добавлять элементы**, но обеспечивает гибкость при работе с разными типами списков, что полезно для методов, предназначенных для чтения данных из списка любого типа.
    
Используйте `List<?>`, когда вам нужно работать с коллекцией неизвестного типа без изменения ее содержимого, и `List<Object>`, когда вы хотите иметь возможность добавлять в список любые объекты.

### **Важное правило (PECS):**

- Если метод **только читает** из коллекции → используйте **`? extends T`**.
    
- Если метод **только записывает** → используйте **`? super T`**.
    
- Если метод **не изменяет коллекцию** → используйте **`List<?>`**.

## **Что такое `extends` и `super` в Generics?**

**Ответ:**

- `? extends T` — ограничение сверху (можно читать как `T`).
    
- `? super T` — ограничение снизу (можно записывать `T` и его подтипы).

## **Что такое PECS (Producer Extends, Consumer Super)?**

**Ответ:** Принцип использования wildcards:

- **Producer (`extends`)** — если коллекция только производит данные (например, `List<? extends Number>`). (если попробовать записать будет ошибка компиляции)
    
- **Consumer (`super`)** — если коллекция принимает данные (например, `List<? super Integer>`). Читать из такой коллекции **можно**, но результат чтения будет иметь тип **`Object`**, а не `Integer`. Это делает такую операцию часто бессмысленной без явного приведения типов.


##  **Как создать Generic-класс и метод?**
```java
class Box<T> {
    private T value;
    public void set(T value) { this.value = value; }
    public T get() { return value; }
}

public <T> void printArray(T[] array) {
    for (T item : array) System.out.println(item);
}
```

## **Можно ли использовать Generics с `static` методами?**
**Ответ:** Да, но параметр типа должен быть объявлен в методе:
```java
public static <T> T getFirst(List<T> list) { return list.get(0); }
```

## **Можно ли перегружать методы с разными Generic-параметрами?**

**Ответ:** Нет, из-за стирания типов (`void print(List<String>)` и `void print(List<Integer>)` — одинаковы в runtime).

## **Что такое "ковариантность" и "контравариантность" в Generics?**

**Ответ:**
- **Ковариантность (`? extends`)** — можно использовать подтипы.
- **Контравариантность (`? super`)** — можно использовать супертипы.

## **Как проверить тип Generic-параметра во время выполнения?**

**Ответ:** Нельзя напрямую из-за стирания типов, но можно передать `Class<T>`:

```java
public <T> void checkType(Object obj, Class<T> type) {
    if (type.isInstance(obj)) { ... }
}
```

## **Можно ли создать экземпляр Generic-типа (`new T()`)?**

**Ответ:** Нет, из-за стирания типов. Решение — передать `Supplier<T>` или использовать рефлексию.

## **Как работает `Collections.max()` с Generics?**
```java
public static <T extends Comparable<? super T>> T max(Collection<? extends T> coll)
```

Принимает коллекцию элементов, сравниваемых через `Comparable`.

## **Что такое "reifiable" и "non-reifiable" типы?**

**Ответ:**
- **Reifiable** — типы, информация о которых доступна в runtime (например, `String`, `Integer[]`).
    
- **Non-reifiable** — типы, стираемые компилятором (например, `List<String>`).

## **Можно ли использовать Generics в `instanceof`?**

**Ответ:** Нет, из-за стирания типов:
```java
if (list instanceof List<String>) // Ошибка!
if (list instanceof List<?>)      // OK
```

## **Как ограничить Generic несколькими типами?**

**Ответ:** Через `&`:
```java
<T extends Comparable<T> & Serializable>
```

## **Можно ли наследовать Generic-класс?**

**Ответ:** Да:
```java
class StringBox extends Box<String> { ... }
```

## **Что такое "raw type" и почему его использование не рекомендуется?**

**Ответ:** Это Generic-тип без указания параметра (например, `List` вместо `List<String>`). Не рекомендуется, т.к. теряется безопасность типов.

## **Как избежать "unchecked cast" предупреждений?**

**Ответ:** Использовать `@SuppressWarnings("unchecked")` или переработать код, чтобы избежать приведения.

## **Как создать Generic-интерфейс?**

```java
interface Repository<T> {
    void save(T entity);
    T findById(int id);
}
```

##  **Можно ли использовать Generics с enum?**

**Ответ:** Да, но enum не может быть Generic:
```java
enum Color<T> { ... } // Ошибка!
```

## **Можно ли использовать `var` с Generics?**

**Ответ:** Да:

```java
var list = new ArrayList<String>();
```

## **Как Generics влияют на производительность?**

**Ответ:** Нет влияния, т.к. информация стирается в runtime.

## **Можно ли писать `List<Number> list = new ArrayList<Integer>();`?**
Нет. Если один тип является подтипом другого (например, `Integer` является подтипом `Number`), **`List<Integer>` не является подтипом `List<Number>`**.

Если вы хотите создать список чисел, который может содержать разные подтипы `Number`, и присвоить ему `ArrayList<Integer>`, вы можете использовать **ограниченные подстановки** с помощью символа подстановки `?`. Однако стоит отметить, что с таким списком вы **не сможете добавить новые элементы**, поскольку компилятор не знает точного типа элементов, но вы можете безопасно читать элементы как объекты типа `Number`

## **Как Generics работают с наследованием?**
1. **Инвариантность обобщенных типов:**
    
    - `List<Dog>` не является подтипом `List<Animal>`, даже если `Dog` является подтипом `Animal`.
2. **Используйте `? extends T` для ковариантности:**
    
    - Когда вы хотите **только читать** данные из коллекции.
    - Вы можете итерироваться по коллекции и обрабатывать объекты как тип `T`.
3. **Используйте `? super T` для контравариантности:**
    
    - Когда вы хотите **только добавлять** данные в коллекцию.
    - Позволяет добавлять объекты типа `T` или его подтипов.
4. **Без ограничений (`<?>`):**
    
    - Используется, когда тип неизвестен.
    - Можно читать объекты типа `Object`.
    - Нельзя добавлять элементы (кроме `null`).

  ```java
  public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    for (int i = 0; i < src.size(); i++) {
        dest.set(i, src.get(i));
    }
}

```

- `List<? extends T> src` — источник, из которого **читаются** данные.
- `List<? super T> dest` — назначение, в которое **записываются** данные.


## **Что такое инвариантность в Generics?**
Инвариантность означает, что обобщенные типы с разными параметрами типа не связаны по наследованию. То есть `List<String>` не является ни подтипом, ни супертипом `List<Object>`.

## **Объясните разницу между `? extends T` и `? super T`.**

- `? extends T` ограничивает тип сверху: принимает `T` или его подтипы. Используется для чтения данных.
- `? super T` ограничивает тип снизу: принимает `T` или его суpertypes. Используется для записи данных.

## **Объясните ограничения при использовании статических членов в обобщенных классах.**

Статические члены обобщенного класса не могут использовать параметр типа, так как он связан с экземпляром класса, а статические члены принадлежат классу в целом.

## **Какие есть ограничения у Java Generics?**

- Нельзя использовать примитивные типы.
- Нельзя создавать экземпляры параметров типа.
- Нельзя создавать массивы обобщенных типов.
- Информация о типах недоступна во время выполнения из-за стирания типов.

## **Можете ли вы использовать рефлексию с Generics?**

Частично. Из-за стирания типов во время выполнения невозможно получить информацию о параметрах типа, однако можно работать с необобщенными частями классов через рефлексию.

## **Как создать обобщенный конструктор в не обобщенном классе?**

Объявляя параметр типа перед именем конструктора:
```java
public class MyClass {
    public <T> MyClass(T param) { /* ... */ }
}

```

## **Можно ли создать Generic-класс с несколькими параметрами типов?**
```java
class Pair<K, V> {
    private K key;
    private V value;
    // конструктор, геттеры, сеттеры
}
```

## **Как сделать так, чтобы Generic-метод возвращал разные типы в зависимости от входного параметра?**

**Ответ:** Через рефлексию:
```java
public <T> T createInstance(Class<T> clazz) throws Exception {
    return clazz.getDeclaredConstructor().newInstance();
}
```

## **Можно ли использовать Generics в аннотациях?**

**Ответ:** Нет, аннотации не поддерживают Generics.

## **Что такое "heap pollution" (загрязнение кучи) в Generics?**

**Ответ:** Ситуация, когда в коллекцию с типом `T` попадает объект другого типа. Пример:
```java
List<String> strings = new ArrayList<>();
List rawList = strings;
rawList.add(123); // Heap pollution: в List<String> лежит Integer
```

## **Как Generics влияют на переопределение методов?**

**Ответ:** Параметры типа должны совпадать:
```java
class Parent {
    void print(List<String> list) { ... }
}
class Child extends Parent {
    @Override
    void print(List<String> list) { ... } // OK
    // void print(List<Integer> list) { ... } // Ошибка!
}
```

## **Что такое "self-bounding generic" (`<T extends Comparable<T>>`)?**

**Ответ:** Ограничение типа, где `T` должен реализовывать `Comparable<T>`:
```java
public static <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) > 0 ? a : b;
}
```
## **Можно ли использовать Generics в lambda-выражениях?**

**Ответ:** Да, если тип объявлен в контексте:

```java
Function<String, Integer> parser = Integer::parseInt;
```

## **Какой тип имеет `List<List<?>>`?**

**Ответ:** Это список списков с неизвестным типом. Пример:

```java
List<List<?>> lists = new ArrayList<>();
lists.add(Arrays.asList(1, 2, 3)); // List<Integer> подходит под List<?>
lists.add(Arrays.asList("A", "B")); // List<String> тоже подходит
```
