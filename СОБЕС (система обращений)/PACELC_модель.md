# PACELC-модель

> Расширение CAP-теоремы.  
> **Ключевая идея:** компромиссы в распределённых системах существуют не только при partition, но и в нормальной работе.

---

## Формула

```
If P → choose A or C
Else → choose L or C
```

| Буква | Расшифровка | Суть |
|---|---|---|
| **P** | Partition | Разрыв сети между узлами |
| **A** | Availability | Отвечаем на запросы, даже если данные могут быть устаревшими |
| **C** | Consistency | Все узлы видят одинаковые данные |
| **E** | Else | Нормальная работа без разделения |
| **L** | Latency | Время отклика (быстрый ответ ≈ асинхронная репликация) |
| **C** | Consistency | То же — строгая согласованность ценой задержки |

---

## Почему CAP недостаточно

CAP описывает только поведение **при partition** — редком событии.  
На практике:

- Данные всегда реплицируются на несколько узлов
- Синхронная репликация = консистентность, но **выше latency**
- Асинхронная репликация = низкая latency, но **eventual consistency**

> CAP игнорирует этот ежедневный trade-off. PACELC его формализует.

---

## Четыре режима

```
               При Partition     В норме
               ──────────────    ────────────
PA / EL   →   Availability   +  Low Latency
PC / EC   →   Consistency    +  Consistency
PA / EC   →   Availability   +  Consistency
PC / EL   →   Consistency    +  Low Latency
```

### Поведение при записи

**PA (partition → availability):**
1. Клиент → узел A: write
2. Узел A не может достучаться до B (разрыв)
3. A отвечает клиенту: OK (данные на A есть, на B — нет)
4. После восстановления связи — догоняющая репликация (anti-entropy)

**PC (partition → consistency):**
1. Клиент → узел A: write
2. Узел A не может достучаться до B
3. A возвращает ошибку / таймаут
4. Операция не выполнена → данные не рассинхронизированы

**EL (else → latency):**
1. Клиент → узел A: write
2. A применяет локально, сразу отвечает: OK
3. Репликация на B идёт **асинхронно** в фоне
4. Чтение с B сразу после — может вернуть старое значение

**EC (else → consistency):**
1. Клиент → узел A: write
2. A **синхронно** реплицирует на B, ждёт подтверждения
3. A отвечает клиенту: OK (оба узла актуальны)
4. Latency выше, зато любое чтение с любого узла консистентно

## Классификация систем

| Система | Режим | Комментарий |
|---|---|---|
| **DynamoDB** | PA / EL | Eventual consistency по умолчанию, максимальная скорость |
| **Cassandra** | PA / EL | Настраиваемые уровни консистентности (QUORUM, ALL, ONE) |
| **Google Spanner** | PC / EC | Строгая сериализуемость, TrueTime + Paxos, +10–100ms latency |
| **HBase** | PC / EC | Синхронная репликация, приоритет целостности |
| **MongoDB** | PA / EC | При partition — failover (A), в норме — чтение с мастера (C) |
| **Cosmos DB** | гибрид | 5 уровней консистентности, можно настроить любой из 4 режимов |
| **PNUTS (Yahoo)** | PC / EL | Редкий кейс: при partition — консистентность, в норме — скорость |
| **Riak** | PA / EL | Аналог Cassandra/Dynamo |
| **DNS** | PA / EL | Реплики расходятся, но система никогда не падает |

---

## Когда что выбирать

| Приоритет | Режим | Примеры задач |
|---|---|---|
| Скорость и доступность | PA / EL | Соцсети, ленты, кэши, рекомендации, DNS |
| Надёжность данных | PC / EC | Финансы, бронирование, инвентарь, платежи |
| Гибридно | Cosmos DB, Cassandra с настройкой | Разные компоненты одного приложения |

> Пример: интернет-магазин — каталог товаров (PA/EL) + корзина (PA/EC) + оформление заказа (PC/EC)

---

## PACELC vs CAP

| | CAP | PACELC |
|---|---|---|
| Когда применяется | Только при partition | Всегда — и при partition, и в норме |
| Что сравнивает | A vs C | A vs C при P; L vs C при Else |
| "CA"-системы | Существуют | Фактически не существуют — нулевой latency нет никогда |
| Учитывает latency | Нет | Да |

---

## Критика

- **Бинарность:** между «строгой консистентностью» и «eventual» — десятки промежуточных моделей (causal, session, monotonic read)
- **Ярлыки обманывают:** большинство систем настраиваемые — MongoDB может быть PA/EL, PA/EC или PC/EC в зависимости от конфигурации
- **Не покрывает:** throughput, изоляция транзакций (ACID/BASE), стоимость операций, fault tolerance узлов

> PACELC — инструмент для постановки правильных вопросов, не строгий закон.
