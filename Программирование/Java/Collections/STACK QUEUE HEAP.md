## STACK - LIFO OR FILO 
Стек поддерживает лишь две базовые операции:
- Положить новый элемент на вершину `O(1)`
- Убрать элемент с вершины `O(1)`

1. `Stack` — стандартная реализация стэка через устаревший `Vector` (динамический массив)
    
2. `LinkedList` — можно использовать связный список в качестве стека. Действительно, в конец мы можем класть новые элементы, и забирать элементы будем тоже только с конца
    
3. `ArrayList` — на самом деле, для стека может подойти любая реализация `List`. В конец кладём, из конца берём.
**Примеры ситуаций, когда стек может быть полезен:**

- Управление вызовами функций (стек вызовов)
    
- Отслеживание истории действий в текстовых редакторах (Undo/Redo) (каждое новое действие добавляется в стек, и отмена извлекает последнее выполненное действие)
    
- Проверка сбалансированности открывающих и закрывающих элементов, таких как скобки, кавычки, теги HTML и т.д.
    
- Выполнением действий в определенном порядке и отслеживание этой последовательности - стек может быть использован для хранения состояния и управления порядком выполнения операций.
    
- Отслеживание глубины рекурсии (в рекурсивных алгоритмах) или обход структур данных (древовидных или графовых)

Если в задаче вы видите, что необходимо отслеживать порядок, структуру или баланс элементов, стек может быть хорошим выбором.

## QUEUE - FIFO

Очередь поддерживает лишь две базовые операции:

- Положить элемент в конец очереди `**O(1)**`
    
- Взять элемент из начала очереди `**O(1)**`

1. `LinkedList` — реализация через связный список. В конец списка добавляем новые элементы, из начала списка достаём
    
2. `ArrayDeque` — реализация через массив. Размер массива автоматически увеличивается, если места начинает не хватать. Как и в случае со стеком, эта реализация, как правило, работает быстрее.

**Примеры ситуаций, когда очередь может быть полезной:**

- Управление задачами в планировщике задач
    
- Моделирование процессов, таких как обслуживание клиентов в банке (очередь на кассе)
    
- Реализация алгоритмов BFS (Breadth-First Search) для обхода графов
    
- Если в задаче требуется частая вставка и извлечение элементов, и они обрабатываются в порядке поступления

В целом, использование очереди часто имеет смысл, когда необходимо управлять порядком выполнения операций и обрабатывать элементы в определенном порядке.

## **Deque (Double-ended queue)** — это двухсторонняя очередь. В Java `Deque` тоже является интерфейсом, и расширяет интерфейс `Queue` еще двумя базовыми операциями:

- Добавить элемент в начало очереди
    
- Взять элемент из конца очереди
    

Таким образом, мы можем вставлять и удалять элементы как с начала, так и с конца двухсторонней очереди. Название весьма говорящее.

Вы, наверное, заметили в разделе с `Queue`, что одна из реализаций называется `**ArrayDeque**`. Слово **Deque** здесь не с проста, эту структуру данных реализует интерфейс `Deque` (тем самым реализует и `Queue` тоже, потому что `Deque` является наследником `Queue`). При этом, `LinkedList` в Java двусвязный, поэтому его тоже можно использовать как `Deque`. Более того, `LinkedList` реализует `Deque`. Таким образом общая схема будет выглядеть данным образом:

Если использовать **Deque** только для добавления в конец и получение из конца, то **Deque** может послужить как стек. Тут главное понять, что стек и очередь — это скорее про интерфейс взаимодействия с внутренней структурой данных (как правило, массив или связный список), нежели про отдельные независимые единицы. Стэк и очередь просто задают правила взаимодействия с данными, а реализация может быть разная, в зависимости от поставленной задачи и требований к ней.

## Heap и PriorityQueue
**Куча (heap)** — это сбалансированное бинарное дерево, на корне которого всегда лежит максимальный или минимальный элемент, в зависимости от выбранного компаратора элементов. Т.е. главным преимуществом данной структуры данных является **доступ в любой момент времени за O(1) к экстремальному элементу** (крайнему элементу) согласно заданному компаратору.

**Куча поддерживает три базовые операции:**

- Посмотреть корневой элемент (максимальный или минимальный) – **`O(1)`**
    
- Удалить корневой элемент – **`O(logN)`**
    
- Добавить новый элемент – **`O(logN)`**
    

Обратите внимание, мы всегда знаем где корневой элемент, и можно всегда прочитать значение очень быстро, тогда как чтобы удалить экстремальное значение, нужно перебалансировать дерево, поэтому сложность уже логарифмическая.

**В Java для реализации кучи используется приоритетная очередь: PriorityQueue

**Примеры применения кучи в сортировке и приоритетных очередях:**

- HeapSort: Сортировка массива с использованием кучи
    
- Приоритетные очереди: Выполнение операций в порядке приоритета, где элементы с более высоким приоритетом извлекаются первыми.

А также heap применяется в алгоритме Дейкстры для поиска кратчайших путей в графе с использованием весов на ребрах и в алгоритме Прима для построения минимального остовного дерева для эффективного выбора следующего шага.

Использование кучи (heap) может быть целесообразным в задачах, которые требуют эффективного доступа к максимальному или минимальному элементу, а также в сценариях, где порядок элементов несущественен, а лишь их приоритет.
