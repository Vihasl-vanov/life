## Map
- Ключи уникальны: Map не допускает дублирующихся ключей.
- Значения могут быть дублирующимися: одно и то же значение может быть связано с разными ключами.

Реализации
- HashMap. Основана на хэш-таблице, обеспечивает быстрый доступ к элементам по ключам. Не гарантирует порядок элементов и позволяет хранить null-ключи и null-значения.
- LinkedHashMap. Основана на хэш-таблице и двусвязном списке, сохраняет порядок вставки элементов и обеспечивает быстрый доступ к элементам по ключам.
- TreeMap. Основана на красно-черном дереве, обеспечивает доступ к элементам по ключам в отсортированном порядке. Не позволяет хранить null-ключи, но допускает null-значения.
## Equals and Hashcode
- equals и hashcode BCЕГДА переопределяются вместе. 
- ОБЯЗАНЫ переопределяться для любого класса, объекты которого используются в качестве ключей в HashMap. Для значений не нужно.
- Переопределяются для ключей потому, что оба используются во внутренней работе HashMap. Потому и переопределяются всегда вместе - нужны оба.
- hashcode должен давать максимально возможное распределение значений для объектов. Т.е. никаких постоянных хэш-кодов для объектов. Иначе все объекты будут иметь один и тот жe hashcode и попадать в одну и ту же ячейку массива Entry.
- equals должен производить сравнение объектов по всем значащим полям с точки зрения логики работы приложения.
- hashCode должен работать по ТЕМ ЖЕ полям, по которым производит сравнение equals. Ни больше, ни меньше. Иначе HashMap будет работать неправильно.

- **Консистентность**. Если два объекта равны согласно методу equals(), их хеш-коды также должны быть равны. Это гарантирует, что равные объекты будут храниться в одном бакете, и операции с ними будут работать правильно.
    
- **Неизменность**. Хеш-код объекта, используемого в качестве ключа, не должен меняться на протяжении его жизненного цикла, поскольку это может привести к непредсказуемому поведению HashMap.

Использование объектов с изменяемыми полями в качестве ключей в HashMap является плохой практикой, поскольку это может привести к непредсказуемому поведению:

## Основные компоненты и принципы работы 
- **Node**. Это объект содержащий ключ, значение, хэш ключа, ссылку на след элемент. 
```java
static class Node<K, V> {
    final int hash;     // Хеш ключа
    final K key;        // Ключ
    V value;            // Значение
    Node<K, V> next;    // Ссылка на следующий узел (для коллизий)
}

static final class TreeNode<K,V> {
    TreeNode<K,V> parent;  // Родительский узел
    TreeNode<K,V> left;    // Левый потомок
    TreeNode<K,V> right;   // Правый потомок
    TreeNode<K,V> prev;    // Предыдущий узел (для удаления)
    boolean red;          // Цвет узла (красный/чёрный)
}
```

- **Массив (бакеты)**. В основе HashMap лежит массив Node. Каждый бакет может содержать null(если мы ничего не положили в него), Один узел Node если коллизий нет и  список или дерево(TreeNode) если есть коллизии.
- **Узлы списка**. Узлы связанного списка представляют собой объекты, содержащие ключ, значение и ссылку на следующий узел. В случае коллизий (когда два разных ключа имеют одинаковый хэш-код), эти объекты образуют цепочку. Т.е. здесь уже несколько пар ключ-значение могут лежать в одном бакете.
- **Хэш-функция**. Благодаря методу hashcode() ключ преобразовывается в хэш-код, который представляет собой интовое число. Затем на основе хэш-кода мапа вычисляет индекс в нашем массиве Node[], куда будет помещена пара ключ-значение (Node).
- **Разрешение коллизий**. В случае коллизии (когда два ключа имеют одинаковый хеш-код), новая пара ключ-значение будет добавлена в связанный список того же бакета. При поиске, вставке или удалении элемента, HashMap будет искать элемент в связанном списке соответствующего бакета.
- **Изменение размера (ресайзинг)**. При достижении определенного порога заполнения (коэффициент заполнения, по умолчанию равный 0.75), происходит изменение размера массива и перераспределение элементов по бакетам. Это делается для поддержания эффективной работы HashMap и уменьшения вероятности возникновения длинных цепочек связанных списков.

2. К полученному хэшу применяется  формула HashMap, которая вычисляет из него индекс в массиве Node[], в который нужно положить этот ключ.

2. К полученному хэшу применяется секретная формула HashMap, которая вычисляет из него индекс в массиве Node[], где хранится наша пара Entry.
3. Значение переданное в метод get() и ключ, который лежит под полученным индексом в массиве Node[] сравниваются через метод equals, чтобы убедиться, что это действительно один и тот же ключ.![[Снимок экрана 2025-04-12 в 10.07.52.png]]

Удаление элемента

1.  У объекта ключа, переданного в remove(), вызывается метод hashCode().
2. К полученному хэшу применяется  формула HashMap, которая вычисляет из него индекс в массиве Node[], где хранится наша пара Node.
3. Значение, переданное в метод remove(), и ключ, который лежит под полученным индексом в массиве Node[], сравниваются через метод equals, чтобы убедиться, что это действительно один и тот же ключ.
4. Когда мы нашли нужный ключ, пара удаляется. Если наш ключ не был найден, то ничего не произойдет, а метод remove вернет нам null.



## TreeMap
`TreeMap` (реализует `NavigableMap`, что в свою очередь наследуется от `SortedMap`) — структура данных, представляющая собой реализацию интерфейса `Map`, основанную на красно-черном дереве.

- Ключи хранятся в отсортированном порядке. Т.е. при обходе элементов, они будут идти в порядке возрастания.
- Быстрый доступ, вставка и удаление за `O(logn)`.
- Ключи уникальны.
- Требует реализацию `Comparable` для типа или передаче `Comparator` в конструктор. Т.к. `TreeMap` нужно правило для сортировки элементов.

Применение TreeMap
- Управление расписанием. Ключи — даты, элементы — планы. Это позволит хранить и легко отображать расписание в хронологическом порядке.
    
- Хранение любых больших данных в отсортированном порядке (всегда находить наименьший и наибольший элемент)
    
- Операции навигации (до, после, между)

## ArrayList

Это динамический массив. То есть не имеет фиксированного размера, в отличие от статического. Это полезно, когда изначально неизвестно, со сколькими элементами будет работать программа.

Элементы массива расположены в памяти по очереди — один за другим. Допустим, у нас есть массив:

```
[1,4,2,7,12,-3,1]
```

Массив, хранит в себе индекс 0-го элемента, с помощью которого мы можем получить доступ к любому элементу за `O(1)` добавив к индексу начала, индекс интересующего нас элемента.

При добавлении в конец, почти  нет никаких проблем. Операция имеет сложность `O(1)`.

Но, если добавить в середину или в начало, нужно сдвинуть элементы справа направо:![[Снимок экрана 2025-04-12 в 09.06.29.png]]

В среднем и в худшем случае, вставка элементов в динамический массив - `O(N)`, так как при ставке в конец, например, может быть достигнута **capacity**, и тогда внутренний массив должен будет увеличиться, что приведет к копированию всех элементов.

Удаление элемента - то же самое что и добавление, только элементы массива движутся налево![[Снимок экрана 2025-04-12 в 09.08.41.png]]
Среднее и худшее время работы - `O(N)`.

Поиск происходит тоже по индексу. Зная индекс начала массива - 0, к нему добавляем интересующий индекс и достаем элемент:![[Снимок экрана 2025-04-12 в 09.09.48.png]]
Всегда - `O(1)`.

`ArrayList` имеет атрибут `capacity` типа `int`, по дефолту 10. При записи в ячейку с индексом `capacity + 1`, происходит динамическое увеличение размера на `(capacity * 3) / 2 + 1` и в него помещаются все элементы из старого массива, а также добавляется новый элемент.

При удалении элемента, `capacity` не меняется и список самостоятельно не уменьшит свой размер. Для явного уменьшения размера, используется метод - `trimToSize()`.
### Проблемы
1. Если размер массива увеличивается, придется копировать весь массив и заполнять новый. Если в определенном сегменте памяти не хватает места для нового размера массива, придется создавать его в другом сегменте.
![[Снимок экрана 2025-04-12 в 09.13.20.png]]
2. При удалении или добавлении какого-либо элемента, все элементы справа будут перемещены для сохранения актуальности индексов. То есть, в этой структуре данных не эффективно часто вставлять и удалять элементы.
3. Необходимо проверять индекс на выход за границы списка.

## LinkedList
это структура данных, которая представляет коллекцию элементов, порядок которых не определяется их физическим расположением в памяти. Вместо этого, каждый элемент указывает (с помощью ссылки) на следующий, и так до конца списка.![[Снимок экрана 2025-04-12 в 09.16.03.png]]

Таким образом, эта структура позволяет эффективно вставлять или удалять за `O(1)` элементы из любой позиции, т.к. нам не важен порядок элементов в памяти. Однако, сложность доступа к элементу списка в среднем составит `O(N)`, т.к. нам нужно пройти по всем элементам списка, пока не найдем интересующий.

Вставка в начало или в конец выполняется за `O(1)`, за счет того, что связный список хранит ссылки на начало и конце списка.

Индексы в `LinkedList` не позволят найти элемент на `O(1)`. Потому что элементы расположены в памяти непоследовательно. Из-за этого нам нужно перебрать все элементы списка, пока не найдем интересующий. Сложность в среднем и в худшем случае — `O(N)`.

Но если мы заранее знаем (например, в кэше) ссылку на элемент после которого хотим вставить новый — `O(1)`.

Чтобы найти элемент, нам нужно пройтись из начала списка до интересующего элемента — `O(N)`.

В `Java`, `LinkedList` реализован как двусвязный список, где каждый элемент имеет ссылку на следующий и предыдущий элементы. Также, структура содержит ссылку на голову (head) и на хвост (tail). `LinkedList` реализует интерфейсы `Deque` и `Queue`, что позволяет использовать его как двустороннюю очередь или очередь с приоритетом.

## Примеры использования ArrayList и LinkedList
`ArrayList` хорош для следующих задач:
- Когда необходимо часто получать доступ к элементам списка по индексу.
- Когда размер списка известен заранее и не изменяется часто.

`LinkedList` хорош для следующих задач:
- Когда необходимо часто добавлять или удалять элементы из середины списка (при условии, что мы заранее знаем указатель на середину).
- Когда размер списка неизвестен заранее и может изменяться часто.
- Когда необходимо обрабатывать большие объемы данных и необходимо минимизировать затраты на копирование элементов при добавлении или удалении.
- Для работы в виде стека или очереди.

## STACK - LIFO OR FILO 
Стек поддерживает лишь две базовые операции:
- Положить новый элемент на вершину `O(1)`
- Убрать элемент с вершины `O(1)`

1. `Stack` — стандартная реализация стэка через устаревший `Vector` (динамический массив)
    
2. `LinkedList` — можно использовать связный список в качестве стека. Действительно, в конец мы можем класть новые элементы, и забирать элементы будем тоже только с конца
    
3. `ArrayList` — на самом деле, для стека может подойти любая реализация `List`. В конец кладём, из конца берём.
**Примеры ситуаций, когда стек может быть полезен:**

- Управление вызовами функций (стек вызовов)
    
- Отслеживание истории действий в текстовых редакторах (Undo/Redo) (каждое новое действие добавляется в стек, и отмена извлекает последнее выполненное действие)
    
- Проверка сбалансированности открывающих и закрывающих элементов, таких как скобки, кавычки, теги HTML и т.д.
    
- Выполнением действий в определенном порядке и отслеживание этой последовательности - стек может быть использован для хранения состояния и управления порядком выполнения операций.
    
- Отслеживание глубины рекурсии (в рекурсивных алгоритмах) или обход структур данных (древовидных или графовых)

Если в задаче вы видите, что необходимо отслеживать порядок, структуру или баланс элементов, стек может быть хорошим выбором.

## QUEUE - FIFO

Очередь поддерживает лишь две базовые операции:

- Положить элемент в конец очереди `**O(1)**`
    
- Взять элемент из начала очереди `**O(1)**`

1. `LinkedList` — реализация через связный список. В конец списка добавляем новые элементы, из начала списка достаём
    
2. `ArrayDeque` — реализация через массив. Размер массива автоматически увеличивается, если места начинает не хватать. Как и в случае со стеком, эта реализация, как правило, работает быстрее.

**Примеры ситуаций, когда очередь может быть полезной:**

- Управление задачами в планировщике задач
    
- Моделирование процессов, таких как обслуживание клиентов в банке (очередь на кассе)
    
- Реализация алгоритмов BFS (Breadth-First Search) для обхода графов
    
- Если в задаче требуется частая вставка и извлечение элементов, и они обрабатываются в порядке поступления

В целом, использование очереди часто имеет смысл, когда необходимо управлять порядком выполнения операций и обрабатывать элементы в определенном порядке.

## **Deque (Double-ended queue)**

Это двухсторонняя очередь. В Java `Deque` тоже является интерфейсом, и расширяет интерфейс `Queue` еще двумя базовыми операциями:

- Добавить элемент в начало очереди
    
- Взять элемент из конца очереди
    

Таким образом, мы можем вставлять и удалять элементы как с начала, так и с конца двухсторонней очереди. Название весьма говорящее.

Вы, наверное, заметили в разделе с `Queue`, что одна из реализаций называется `**ArrayDeque**`. Слово **Deque** здесь не с проста, эту структуру данных реализует интерфейс `Deque` (тем самым реализует и `Queue` тоже, потому что `Deque` является наследником `Queue`). При этом, `LinkedList` в Java двусвязный, поэтому его тоже можно использовать как `Deque`. Более того, `LinkedList` реализует `Deque`. Таким образом общая схема будет выглядеть данным образом:

Если использовать **Deque** только для добавления в конец и получение из конца, то **Deque** может послужить как стек. Тут главное понять, что стек и очередь — это скорее про интерфейс взаимодействия с внутренней структурой данных (как правило, массив или связный список), нежели про отдельные независимые единицы. Стэк и очередь просто задают правила взаимодействия с данными, а реализация может быть разная, в зависимости от поставленной задачи и требований к ней.

## Heap и PriorityQueue
**Куча (heap)** — это сбалансированное бинарное дерево, на корне которого всегда лежит максимальный или минимальный элемент, в зависимости от выбранного компаратора элементов. Т.е. главным преимуществом данной структуры данных является **доступ в любой момент времени за O(1) к экстремальному элементу** (крайнему элементу) согласно заданному компаратору.

**Куча поддерживает три базовые операции:**

- Посмотреть корневой элемент (максимальный или минимальный) – **`O(1)`**
    
- Удалить корневой элемент – **`O(logN)`**
    
- Добавить новый элемент – **`O(logN)`**
    

Обратите внимание, мы всегда знаем где корневой элемент, и можно всегда прочитать значение очень быстро, тогда как чтобы удалить экстремальное значение, нужно перебалансировать дерево, поэтому сложность уже логарифмическая.

**В Java для реализации кучи используется приоритетная очередь: PriorityQueue

**Примеры применения кучи в сортировке и приоритетных очередях:**

- HeapSort: Сортировка массива с использованием кучи
    
- Приоритетные очереди: Выполнение операций в порядке приоритета, где элементы с более высоким приоритетом извлекаются первыми.

А также heap применяется в алгоритме Дейкстры для поиска кратчайших путей в графе с использованием весов на ребрах и в алгоритме Прима для построения минимального остовного дерева для эффективного выбора следующего шага.

Использование кучи (heap) может быть целесообразным в задачах, которые требуют эффективного доступа к максимальному или минимальному элементу, а также в сценариях, где порядок элементов несущественен, а лишь их приоритет.


## Set
- Элементы уникальны. Если попытаться добавить элемент, который уже содержится в множестве, он просто перезапишется.
- У множества отсутствует индексация, т.е. элементы не упорядочены.
- Можно быстро проверить, содержится ли какой элемент в множестве.
- Размер множества динамичен.
- Популярные реализации — `HashSet`, `TreeSet`, `LinkedHashSet`.

`HashSet` основан на хэш-функции. По сути, такой же как `HashMap`, только без элементов.В качестве значения выступает объект заглушка (в коде называется `PRESENT`), для работоспособности `HashMap`.

У `HashSet` тоже могут возникать коллизии, поведение такое же, как и у `HashMap`.
Сложность в среднем — `O(1)`, в худшем — `O(N)`. Может стать `O(logn)`. Все как у `HashMap`.

TreeSet Операции поиска `get` в `TreeSet` нет, потому что `TreeSet` реализует интерфейс `SortedSet`, который не предоставляет такой операции, в отличии от `List` или `Map`, где элементы доступны по индексу.


## EnumMap (`java.util.EnumMap`)

**Особенности:**

- **Ключи:** Предназначен _исключительно_ для ключей типа `enum`.
    
- **Скорость:** Чрезвычайно быстрый и эффективный по памяти. Под капотом использует простой массив, где индексом является порядковый номер элемента `enum` (`ordinal()`). Это дает константное время выполнения `O(1)` для основных операций (`get`, `put`, `containsKey`).
    
- **Порядок:** Итерация по карте происходит в порядке объявления элементов перечисления (естественный порядок `enum`).
    
- **Null-ключи:** Не допускаются. Выбрасывает `NullPointerException`.
    
- **Потокобезопасность:** Нет (как и большинство Map), требуется внешняя синхронизация.
    

**Идеальный use-case:** Любая ситуация, где ключами выступают заранее известные константы перечисления.

## WeakHashMap (`java.util.WeakHashMap`)

**Особенности:**

- **Сборка мусора:** Ключи в этой мапе имеют **слабые ссылки (Weak References)**. Это означает, что если на ключ нет больше "сильных" ссылок (обычных ссылок в вашем коде), он может быть собран сборщиком мусора (Garbage Collector), и соответствующая запись (ключ-значение) автоматически удалится из карты.
    
- **Поведение:** Полезно для создания кэшей или хранилищ метаданных, где записи должны автоматически исчезать, когда ключевой объект больше не используется в основном коде.
    
- **Важно:** Значения имеют обычные (strong) ссылки на ключи. Чтобы значение могло быть собрано, когда ключ удален, используйте структуры вроде `WeakReference` и для значения.
## IdentityHashMap (`java.util.IdentityHashMap`)

**Особенности:**

- **Сравнение:** Для сравнения ключей использует **ссылку (`==`)**, а не метод `equals()`. Это означает, что два ключа считаются равными, только если это один и тот же объект в памяти.
    
- **Хэширование:** Вместо вызова `key.hashCode()` использует `System.identityHashCode(key)`, который вычисляет хэш-код на основе внутреннего адреса объекта (даже если метод `hashCode()` объекта переопределен).
    
- **Назначение:** Предназначена для специальных задач, таких как сериализация, трассировка объектов или поддержание "канонических" представлений (как в `String.intern()`).
    
- **Производительность:** Быстрее `HashMap` в некоторых сценариях, так как не требует глубокого сравнения через `equals()`.

## `ConcurrentHashMap` 

- **Назначение:** Потокобезопасный аналог `HashMap`.
    
- **Механизм безопасности:**
    
    - **Не использует глобальную блокировку.** Вместо этого применяется **блокировка на уровне сегментов/бакетов** (в Java 7) или вообще **lock-free алгоритмы** (CAS-операции) для чтения и некоторых операций записи (в Java 8+).
        
    - Чтение (в т.ч. итерация) происходит **без блокировок**.
        
- **Итератор:** Предоставляет **слабую согласованность (weakly consistent)**. Он отражает состояние карты на момент своего создания _или_ более позднее, но никогда не выбрасывает `ConcurrentModificationException`.
    
- **Nulls:** **Не разрешает** использование `null` в качестве ключа или значения.
    
- **Производительность:** Очень высокая, так как потоки могут работать с разными частями (сегментами) карты одновременно.
    
- **Особые методы:** Предоставляет атомарные операции `putIfAbsent()`, `compute()`, `computeIfAbsent()`, `computeIfPresent()`, `merge()`, которые позволяют выполнять сложные проверки-и-действия без внешней синхронизации.
    

**Идеально для:** Высоконагруженных многопоточных кэшей, конфигураций, хранилищ данных.

## `CopyOnWriteArrayList`  / `CopyOnWriteArraySet` 

- **Назначение:** Потокобезопасные аналоги `ArrayList` и `HashSet`.
    
- **Механизм безопасности:**
    
    - **"Copy-on-Write"**: Любая операция **изменения** (`add`, `set`, `remove`) приводит к созданию **полной копии** внутреннего массива. Изменения применяются к копии, после чего она атомарно подменяет старый массив.
        
    - **Чтение** всегда происходит из старого (неизменного) массива **без какой-либо блокировки**.
        
- **Итератор:** Использует **snapshot** (снимок) массива на момент создания итератора. Гарантированно не выбрасывает `ConcurrentModificationException`
    
- **Производительность:**
    
    - **Чтение:** Очень быстрое (нет блокировок).
        
    - **Запись:** Очень медленная и дорогая по памяти (из-за копирования всего массива). `CopyOnWriteArraySet` реализован поверх `CopyOnWriteArrayList`.
        
- **Идеально для:** Сценариев, где **чтение сильно преобладает над записью** (например, список слушателей (listeners) в событиях, rarely-changed конфиги).

## `ConcurrentSkipListMap` / `ConcurrentSkipListSet`

- **Назначение:** Потокобезопасные аналоги `TreeMap` и `TreeSet`.
    
- **Механизм безопасности:** Используют сложную структуру данных **Skip List** (список с пропусками), которая позволяет выполнять операции без глобальной блокировки, используя `compareAndSet` (CAS).
    
- **Особенности:**
    
    - Элементы хранятся **отсортированными** (по натуральному порядку или `Comparator`).
        
    - Поддерживают конкурентное выполнение операций `put`, `get`, `remove`.
        
- **Итератор:** Слабая согласованность.
    
- **Идеально для:** Потокобезопасных коллекций, где требуется порядок элементов.

## `BlockingQueue` и ее реализации

Интерфейс для очередей, которые поддерживают операции **ожидания** (блокировки потока) при попытке добавить элемент в полную очередь или извлечь из пустой.

**Основные реализации:**

- **`ArrayBlockingQueue`**: Очередь на основе массива фиксированной емкости (bounded). Использует **одну глобальную блокировку** (часто `ReentrantLock`).
    
- **`LinkedBlockingQueue`**: Очередь на основе связного списка. Может быть как bounded, так и unbounded (по умолчанию `Integer.MAX_VALUE`). Использует **две блокировки** (для head и tail), что повышает пропускную способность.
    
- **`PriorityBlockingQueue`**: Потокобезопасный аналог `PriorityQueue`. Элементы извлекаются в соответствии с приоритетом. Неограниченная емкость (unbounded).
    
- **`SynchronousQueue`**: Очередь **без внутренней емкости**. Каждая операция `put` ждет соответствующую операцию `take` из другого потока, и наоборот. Полезен для обмена данными "handoff".
    

**Идеально для:** Паттерна **"Producer-Consumer"** (Производитель-Потребитель), пулов потоков (как в `Executors.newFixedThreadPool`).


## `ConcurrentLinkedQueue` / `ConcurrentLinkedDeque`

- **Назначение:** Неблокирующие (non-blocking) thread-safe очереди на основе связных списков.
    
- **Механизм безопасности:** Используют **lock-free алгоритмы** (CAS) для достижения потокобезопасности.
    
- **Особенности:**
    
    - **Неограниченная** (unbounded) емкость.
        
    - **Не блокируют** потоки. Операции `add`/`poll` завершаются мгновенно (успешно или нет), в отличие от `BlockingQueue`, где поток может ждать.
        
    - **Итератор:** Слабая согласованность.
        
- **Идеально для:** Сценариев, где множество потоков должны быстро добавлять и удалять элементы из общей очереди без простоя.
