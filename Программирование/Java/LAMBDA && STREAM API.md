## Терминальные и Промежуточные операции
**Промежуточные операции**(Intermediate Operations) - ленивые выполняются только при вызове терминальной операции. Возвращают новый `Stream`, позволяя строить цепочки вызовов (method chaining)
### Фильтрация и выбор:
- `filter(Predicate<T>)` - фильтрация элементов
- `distinct()` - удаление дубликатов
- `limit(long n)` - ограничение количества элементов
- `skip(long n)` - пропуск первых n элементов

### Преобразование:
- `map(Function<T,R>)` - преобразование элементов
- `flatMap(Function<T,Stream<R>>)` - "разворачивание" вложенных структур
- `mapToInt()`, `mapToLong()`, `mapToDouble()` - преобразование в примитивные стримы

### Сортировка и просмотр:
- `sorted()` - сортировка (натуральным порядком)
- `sorted(Comparator<T>)` - сортировка компаратором
- `peek(Consumer<T>)` - выполнение действия без изменения элементов

**Терминальные операции** - запускают выполнение всего pipeline. После выполнения поток нельзя использовать повторно.
### Итерация:
- `forEach(Consumer<T>)` - выполнение действия для каждого элемента
- `forEachOrdered(Consumer<T>)` - сохранение порядка в параллельных стримах

### Сбор результатов:
- `collect(Collector<T,A,R>)` - сбор элементов (например, в коллекцию)
- `toArray()` - преобразование в массив
- `toArray(IntFunction<A[]>)` - преобразование в массив определенного типа

### Поиск и проверка:
- `anyMatch(Predicate<T>)` - хотя бы один элемент соответствует
- `allMatch(Predicate<T>)` - все элементы соответствуют
- `noneMatch(Predicate<T>)` - ни один элемент не соответствует
- `findFirst()` - первый элемент
- `findAny()` - любой элемент (в параллельных стримах)

### Агрегация:
- `count()` - подсчет элементов
- `min(Comparator<T>)` - минимальный элемент
- `max(Comparator<T>)` - максимальный элемент
- `reduce(BinaryOperator<T>)` - свертка элементов
- `reduce(T, BinaryOperator<T>)` - свертка с начальным значением

### Примитивные стримы:
- `sum()` - сумма (для Int/Long/DoubleStream)
- `average()` - среднее значение
- `summaryStatistics()` - статистика (сумма, среднее, min, max, count)

## **Чем отличаются `map` и `flatMap` в стримах?**

**Ответ:**

- **`map`:** Применяет функцию к каждому элементу стрима и заменяет элемент результатом функции. Если функция возвращает коллекцию, то результат будет вложенной коллекцией.
    
    **Пример:**
```java
List<String> words = Arrays.asList("Java", "Stream");
List<Integer> lengths = words.stream()
                             .map(String::length)
                             .collect(Collectors.toList()); // [4, 6]

```

**`flatMap`:** Применяет функцию к каждому элементу и «разворачивает» вложенные структуры, создавая единый стрим.

**Пример:**
```java
List<List<String>> listOfLists = Arrays.asList(
    Arrays.asList("A", "B"),
    Arrays.asList("C", "D")
);
List<String> flatList = listOfLists.stream()
                                   .flatMap(List::stream)
                                   .collect(Collectors.toList()); // [A, B, C, D]

```

##  **Как работают параллельные стримы и какие преимущества они дают?**

**Ответ:** Параллельные стримы обрабатывают элементы параллельно, используя несколько потоков ForkJoinPool, что может повысить производительность на многоядерных процессорах при обработке больших объемов данных.

```java
List<Integer> numbers = IntStream.rangeClosed(1, 1000000).boxed().collect(Collectors.toList());
long count = numbers.parallelStream()
                    .filter(n -> n % 2 == 0)
                    .count();

```
**Преимущества:**

- Ускорение обработки больших коллекций за счет распределения нагрузки между ядрами процессора.

**Недостатки:**

- Может ухудшить производительность для небольших коллекций из-за накладных расходов на управление потоками.
- Не всегда безопасно для операций, не являющихся потокобезопасными.

## **Что такое терминальная операция `collect` и какие есть методы сбора?**

**Ответ:** `collect` — терминальная операция, которая преобразует элементы стрима в коллекцию или другой контейнер. Она принимает `Collector`, который определяет способ сбора элементов.

**Популярные методы сбора:**

- `Collectors.toList()`: Собирает в `List`.
- `Collectors.toSet()`: Собирает в `Set`.
- `Collectors.toMap()`: Собирает в `Map`.
- `Collectors.joining()`: Объединяет строки.
- `Collectors.groupingBy()`: Группирует элементы по ключу.
- `Collectors.partitioningBy()`: Разделяет элементы на две группы по предикату.

## **Как избежать `ConcurrentModificationException` при использовании стримов?**

**Ответ:** `ConcurrentModificationException` возникает, если структура коллекции изменяется во время итерации. Чтобы избежать этого при использовании стримов:

- Не изменяйте коллекцию во время обработки стрима.
- Если нужна параллельная модификация, используйте потокобезопасные коллекции, такие как `ConcurrentHashMap` или `CopyOnWriteArrayList`.
- Используйте подходящие операции стримов, которые не требуют модификации источника.

## **Как реализовать параллельную обработку стримов и какие риски с этим связаны?**

**Ответ:** Параллельную обработку стримов можно реализовать с помощью метода `parallelStream()` или преобразованием обычного стрима с помощью `parallel()`.

**Риски и внимание:**

- **Непотокобезопасные операции:** Некоторые операции или состояния объектов могут быть небезопасны при параллельной обработке.
- **Порядок выполнения:** В параллельных стримах порядок элементов может быть неопределенным, если только не используются упорядоченные коллекции и операции.
- **Производительность:** Параллельные стримы могут не дать преимуществ на небольших объемах данных из-за накладных расходов на управление потоками.
- **Детерминированность:** Параллельные стримы могут приводить к непредсказуемым результатам, если используются небезопасные состояния.

## **Можно ли изменять исходные данные внутри операций стримов? Почему это не рекомендуется?**

**Ответ:** Технически можно изменять исходные данные внутри операций стримов, но это не рекомендуется по нескольким причинам:

- **Несогласованность данных:** Параллельные стримы могут приводить к непредсказуемым результатам при изменении данных.
- **Неочевидное поведение:** Изменение состояния объектов во время стрима усложняет понимание кода и его отладку.
- **Нарушение принципов функционального программирования:** Стримы предполагают неизменяемость данных, что повышает безопасность и предсказуемость.

## **Чем отличаются `Stream` от `Collection` в Java?**

**Ответ:**

- **`Collection`:**
    
    - Представляет собой объект, хранящий множество элементов.
    - Поддерживает дополнительные операции, такие как добавление, удаление, проверка наличия элементов.
    - Хранит данные в памяти.
- **`Stream`:**
    
    - Представляет поток данных, которые могут быть обработаны последовательно или параллельно.
    - Не хранит данные; он вычисляет элементы по мере необходимости.
    - Поддерживает функциональные операции для обработки данных (например, `map`, `filter`).
    - Может быть одноразовым — после выполнения терминальной операции стрим становится недоступен.

**Основные отличия:**

- **Хранилище vs. Трансформация:** `Collection` хранит данные, `Stream` — предоставляет возможности для их обработки.
- **Изменяемость:** `Collection` изменяемая, `Stream` неизменяемый.
- **Повторное использование:** `Collection` можно многократно использовать, `Stream` — нет.

## **Что такое `Optional` API и как избежать его неправильного использования?**

**Ответ:** `Optional` — это контейнерный класс, предназначенный для представления наличия или отсутствия значения, что помогает избежать `NullPointerException` и выразить намерения метода явно.

**Основные методы `Optional`:**

- `of(T value)`: Создает Optional с заданным значением, не допускает `null`.
- `ofNullable(T value)`: Создает Optional, допускает `null`.
- `isPresent()`: Проверяет, содержит ли Optional значение.
- `ifPresent(Consumer<? super T> consumer)`: Выполняет действие, если значение присутствует.
- `orElse(T other)`: Возвращает значение или указанное по умолчанию.
- `orElseGet(Supplier<? extends T> other)`: Возвращает значение или результат поставщика.
- `orElseThrow(Supplier<? extends X> exceptionSupplier)`: Возвращает значение или выбрасывает исключение.

**Избежание неправильного использования:**

- **Не использовать `Optional` в качестве полей класса или параметров методов.** `Optional` предназначен для возвращаемых значений методов.
- **Не применять `Optional.get()` без предварительной проверки `isPresent()`,** так как это может привести к `NoSuchElementException`.
- **Использовать предпочитаемые методы (`ifPresent`, `orElse`, `orElseGet`) вместо явного извлечения значения.**
