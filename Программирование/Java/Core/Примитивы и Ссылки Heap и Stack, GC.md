
## 1. Примитивные типы:
- Хранят **значение напрямую** (в стеке).
- Фиксированный размер (например, `int` – 4 байта, `double` – 8 байт).

## 2. Ссылочные типы:
- Хранят **ссылку** (адрес объекта в куче), сам объект – в хипе.
- Размер зависит от объекта.
- Примеры: `String`, `Object`, массивы (`int[]`).

### Ключевые отличия:
- Примитивы сравниваются через `==` (по значению), ссылки – через `equals()` (или `==` для проверки ссылок).
- Примитивы не могут быть `null`, ссылки – могут.

---

### В стэке хранится:
- Примитивы
- Ссылки на объекты (но не сами объекты)
- Вызовы методов (стэк вызовов)

Стек имеет фиксированный размер памяти, обычно задается при запуске JVM. Очищение происходит автоматически при выходе из метода. Если память стека полностью занята, то Java Runtime бросает исключение `java.lang.StackOverflowError`

### В куче хранится:
- Объекты (всё, что создано через `new`).
- Статические переменные.
- Строки (пул строк).

Куча динамически расширяется до `Xmx`(макс размер кучи) и делится на **Young Generation** (Eden, S0/S1) и **Old Generation**. Очищается с помощью **Garbage Collector**. Если заполнена память кучи, то бросается исключение `java.lang.OutOfMemoryError: Java Heap Space`.

---

## Garbage Collector
**Garbage Collector** — механизм в JVM для **автоматического освобождения памяти** от неиспользуемых объектов. Он нужен для удаления объектов, на которые больше нет ссылок, предотвращая `OutOfMemoryError`. Освобождает от ручного управления памятью.

### Как работает?
Память кучи (Heap) делится на **поколения**:
1. **Young Generation**
    - **Eden**: новые объекты.
    - **Survivor (S0, S1)**: выжившие после минорного GC (копируются между S0 и S1).
    - **Minor GC**: частые, быстрые сборки мусора в Young Gen.

2. **Old Generation**
    - Долгоживущие объекты (пережившие несколько циклов в Survivor).
    - **Major GC (Full GC)**: редкие, но медленные сборки (проверяет всю кучу).

3. **Metaspace** (ранее PermGen)
    - Хранит метаданные классов (не является частью кучи).

---

### Пример алгоритмов GC
- **Serial GC** — однопоточный (для малых приложений).
- **Parallel GC** — многопоточный (баланс скорости/памяти).
- **G1 GC** — гибкий (разбивает кучу на регионы).
- **ZGC/Shenandoah** — низколатентные (паузы < 1 мс).

- Xms - начальный размер кучи при запуске приложения.
- Xmx - максимальный размер кучи.
- Xss - Устанавливает размер стека для каждого потока

# 10 массивов по 1000 элементов or 1000 массивов по 10 элементов. 

## Сравнение типов хранения
   - 10 массивов по 1000 элементов.  
   - В памяти: 1000 элементов хранятся последовательно, что эффективно для кэширования.  
   - Метаданные: требуется всего 10 хэдеров.  

   - 1000 массивов по 10 элементов.  
   - В памяти: элементы плохо хранятся в кэше из-за разрозненности.  
   - Метаданные: требуется 1000 хэдеров, что увеличивает накладные расходы.

## Итог
У массивов и объектов есть мета информация (header’ы в куче).
Массив 10 массивов по 1000 элементовпредпочтительнее:  
- Эффективнее использует кэш.  
- Требует меньше памяти для хранения метаданных.

## Верно ли утверждение, что примитивные типы данных всегда хранятся в стеке, а экземпляры ссылочных типов данных в куче?

Не совсем. Примитивное поле экземпляра класса хранится не в стеке, а в куче. Любой объект (всё, что явно или неявно создаётся при помощи оператора `new`) хранится в куче.
