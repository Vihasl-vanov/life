1. **Что такое Apache Kafka?**  
    _Ответ:_ Kafka — это распределённая потоковая платформа для публикации, хранения и обработки потоков данных в реальном времени. Она используется для построения масштабируемых и отказоустойчивых data pipelines.
    
2. **Какие основные компоненты Kafka?**  
    _Ответ:_
- **Producer (Производитель)** — приложение, которое публикует сообщения в топики Kafka
- **Consumer (Потребитель)** — приложение, которое подписывается на топики и читает сообщения
- **Broker (Брокер)** — сервер Kafka, который принимает, хранит и распределяет сообщения. В кластере Kafka может быть несколько брокеров
- **Topic (Топик)** — логическое разделение, по которому организуются данные. Производители отправляют сообщения в топики, а потребители читают из них
- **Partition (Раздел)** — каждый топик разделён на партиции для параллельной обработки. Сообщения в партициях упорядочены
- **Zookeeper** — сервис, используемый Kafka для управления состоянием кластера и координации брокеров. Однако в новых версиях Kafka отказывается от Zookeeper в пользу собственного механизма метаданных KRaft (Kafka Raft). Это новая внутренняя архитектура метаданных Kafka, которая устраняет зависимость от Zookeeper. Она основана на Raft-консенсусе, позволяя Kafka брокерам самостоятельно управлять метаданными и координировать взаимодействие между собой.

3. **Зачем нужны партиции в Kafka?**  
    _Ответ:_ Партиции позволяют масштабировать обработку данных:
    
    - Увеличивают пропускную способность (параллельное чтение/запись).
        
    - Позволяют распределять данные между брокерами.
4. **Что такое offset?**  
    _Ответ:_ Offset — это уникальный идентификатор сообщения внутри партиции. Consumer использует offset для отслеживания своей позиции.

5. **Как Kafka обеспечивает отказоустойчивость?**  
    _Ответ:_
    
    - Репликация партиций (replication factor).
        
    - Лидеры и follower-ы (ISR – In-Sync Replicas).
        
    - Если брокер падает, его партиции переизбираются на других брокерах.
6. **Как работает Producer в Kafka?**  
    _Ответ:_
    
    - Отправляет сообщения в партиции топика.
        
    - Может использовать ключ (key) для определения партиции (хеширование).
        
    - Подтверждение (acks=0/1/all) гарантирует доставку.
7. **Что такое acks в Producer?**  
    _Ответ:_
    
    - `acks=0` – нет подтверждения.
        
    - `acks=1` – подтверждение от лидера.
        
    - `acks=all` – подтверждение от всех реплик ISR.
8. **Как работает Consumer в Kafka?**  
    _Ответ:_
    
    - Читает сообщения из партиций.
        
    - Группы потребителей (consumer groups) позволяют масштабировать чтение.
        
    - Каждый consumer в группе читает уникальный набор партиций.
        
9. **Что такое Consumer Group?**  
    _Ответ:_ Группа потребителей, совместно обрабатывающих сообщения из топика. Каждая партиция топика обрабатывается только одним consumer в группе.
    
10. **Как Kafka гарантирует порядок сообщений?**  
    _Ответ:_ В пределах одной партиции сообщения хранятся и читаются строго по порядку offset. Между партициями порядок не гарантируется.

11. **Как Kafka хранит сообщения?**  
    _Ответ:_
    
    - Сообщения хранятся в партициях в виде сегментов (segment files).
        
    - У каждого сегмента есть ограничение по времени и размеру (log.retention.hours, log.segment.bytes).
        
12. **Что такое retention policy?**  
    _Ответ:_ Политика хранения сообщений:
    
    - По времени (log.retention.hours).
        
    - По размеру (log.retention.bytes).
        
13. **Как работает compaction в Kafka?**  
    _Ответ:_ Удаляет старые дубликаты по ключу, оставляя только последнее значение. Полезно для топиков вида "ключ-значение".
14. **Что такое ISR (In-Sync Replicas)?**  
    _Ответ:_ Набор реплик, которые синхронизированы с лидером. Если реплика отстаёт, она исключается из ISR.
    
15. **Как выбирается лидер партиции?**  
    _Ответ:_ Лидер выбирается через механизм контроллера Kafka (ранее через ZooKeeper).
    
16. **Что происходит, если лидер партиции падает?**  
    _Ответ:_ Контроллер Kafka выбирает новую реплику-лидер из ISR.

17. **Как увеличить пропускную способность Kafka?**  
    _Ответ:_
    
    - Увеличить число партиций.
        
    - Настроить batch.size и linger.ms у Producer.
        
    - Оптимизировать размер сообщений (сжатие).
        
18. **Какие механизмы сжатия поддерживает Kafka?**  
    _Ответ:_ gzip, snappy, lz4, zstd.
    
19. **Как избежать потери сообщений?**  
    _Ответ:_
    
    - Использовать `acks=all` в Producer.
        
    - Настроить `min.insync.replicas`.
        
    - Обрабатывать ошибки в Producer (retries).
20. **Что такое Kafka Connect?**  
    _Ответ:_ Инструмент для интеграции Kafka с внешними системами (БД, облако и т. д.).
    
21. **Что такое Kafka Streams?**  
    _Ответ:_ Библиотека для обработки потоков данных в реальном времени.
22. **Что такое Exactly-Once Semantics (EOS)?**  
    _Ответ:_ Гарантия, что сообщение будет обработано ровно один раз (достигается через transactional Producer и `isolation.level=read_committed`).
    
23. **Как работает Kafka без ZooKeeper (KRaft)?**  
    _Ответ:_ В Kafka 3.0+ появился режим KRaft (Kafka Raft), где метаданные управляются самими брокерами через Raft-протокол.
    
24. **Что такое Schema Registry?**  
    _Ответ:_ Сервис для управления схемами сообщений (Avro, Protobuf), чтобы избежать конфликтов версий.
    
25. **Как мониторить Kafka?**  
    _Ответ:_ Через JMX, Prometheus + Grafana, или инструменты Confluent Control Center.
    
26. **Какие альтернативы Kafka вы знаете?**  
    _Ответ:_ RabbitMQ, Apache Pulsar, AWS Kinesis, Google Pub/Sub.
